三、实现要点

长按判定：power_key_fsm 是纯逻辑状态机（只依赖 stdint.h/stdbool.h）。PRESS 清零计时，TICK 累加到阈值时进入 POWER_KEY_LONG 并只返回一次 true，RELEASE 在 IDLE/PRESSED/LONG 下都不触发动作。因此短按绝不会误关机，长按也不会重复调用关机。

关机顺序与 main_exit() 一致（iio_shutdown() + 四组 settings_*_save() + vt_enable()），再 sync() 后请求内核断电。power.c 对项目内函数只做 extern 声明、不 include 其头文件，使本模块能脱离 LVGL/settings 依赖单独编译测试。

可测试性：定义 POWER_TEST_STUB 时 power_shutdown() 跳过 reboot()，测试可以安全验证保存与判定逻辑；定义 POWER_BOOT_HOLD_STRICT 时，未检测到电源键保持按下才执行断电（默认关闭）。

为什么"长按开机"默认不强制：CPU 断电期间没有任何软件运行，Linux 启动到 GUI 又要数秒，此时用户早已松开按键。如果按"启动时按键未按住就关机"来判定，会把正常开机误判为短按而变砖。因此软件只做状态读取与接口预留，真正的长按计时/电源自锁必须由电源电路或 FPGA 完成；读取设备或 ioctl 失败时一律保持开机。

五、子模块处理说明

Firmware/gui 原本是 gitlink 子模块（remote 指向上游 strijar/brass_gui），源码改动无法随主仓库提交。本次已移除该 gitlink、删除 Firmware/gui/.git，把 GUI 全部自有源码（含本次新增的 power.c/power.h/tests/）纳入主仓库，一次提交即可带走。

嵌套的第三方 Firmware/gui/lvgl 仍保留为子模块，并在主仓库 .gitmodules 中重新登记路径与上游 URL。原因：LVGL 9.5 目录为 182 MB / 4848 个文件（其中 tests 69 MB、demos 30 MB、src 仅 26 MB），整目录扁平化会让仓库体积暴增且难以跟随上游更新；而本机缺目标工具链，无法验证"精简掉 docs/examples/tests 后仍能构建"，贸然删除第三方文件有构建失败风险。

因此克隆后需要初始化该子模块：

git clone --recurse-submodules https://github.com/liupei404/TRX-Brass.git
# 或已克隆时：
git submodule update --init --recursive

由于 brass-gui.mk 已改为使用本地 Firmware/gui 源码，LVGL 子模块初始化后即可直接构建，不再需要上游 brass_gui 仓库。

六、已知限制与后续

  • 长按开机：软件侧只提供状态校验接口与统一阈值，真正的上电计时/电源自锁需硬件或 FPGA 配合。POWER_BOOT_HOLD_STRICT 默认关闭，启用前须由 U-Boot/FPGA 传递按键保持状态。
  • 电源键设备节点：POWER_BOOT_KEY_DEV 默认 /dev/input/event3，若板级设备号不同可在编译时覆盖；读取失败一律保持开机。
  • 内核断电能力：reboot(RB_POWER_OFF) 需要内核 poweroff 驱动。设备树里 syscon-poweroff 节点仍被注释，若无硬件断电寄存器，将走 main_exit() 回退（GUI 有序退出但系统不断电）。
  • 短按：按需求保持 backlight_switch() 不变。
  • 完整编译验证：需在有 Buildroot 工具链与目标 sysroot 的环境执行，命令见第四节。
